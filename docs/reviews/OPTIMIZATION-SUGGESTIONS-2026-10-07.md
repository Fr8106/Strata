**结论：项目有优化空间，而且最大的收益不在 P4-A 这条线上。**

## 一、先测什么

交接文档里缺三类关键数据：decode tok/s、prefill 一个 chunk 内 GPU 的空闲占比、真实使用中的 prompt 长度和前缀复用率。没有这些，优化排序只能靠猜。

建议先用 Nsight Systems 抓一段 prefill 和一段 decode 的时间线，看 PCIe 传输、GPU 计算、CPU miss 路径是否真正重叠。

## 二、优化方向

### 方向一：prefill 的流水线与 chunk 大小（收益最大）

瓶颈判断：prefill 一个 chunk 基本会用到大部分专家，非驻留的约 24 GiB 要过一遍 PCIe。本机 PCIe 4.0 x16 约 25 GB/s，所以一次扫描约 1 s，吞吐近似等于 chunk 的 token 数除以 1 s。

- chunk 开大：chunk 越大，传输越被摊薄。
- 双缓冲预取：计算第 l 层时，同时预取第 l+1 层的非驻留专家。prefill 阶段这一层的专家集合几乎可以预知，是整层预取。
- 不靠大规模注册：配合"小 pinned 环形缓冲 + 多线程 memcpy"，可能拿到 P4-A 的大部分收益，又不用 pin 46.8 GiB。前面审核里的方案 C 就是这个。

### 方向二：减少 prefill 的次数（对话和前缀缓存）

对话缓存已经有 6 GiB 配置。如果真实使用是 agent 或编码这类长前缀反复出现的场景，前缀命中率对体验的影响，可能比 prefill 从 3.1k 提到 6k 还大。建议记录请求级日志，统计命中率，再决定是否值得做以下几项：

- 扩大缓存；
- 把 KV 落到 NVMe 做持久前缀缓存；
- 优化前缀匹配策略。

### 方向三：缓存策略本身

- 用 profile 给 usage 播种：重启后 usage 从 0 开始，早期 victim 选择接近任意，固定区部分补了这个洞。
- 换成更成熟的淘汰策略：如 TinyLFU、ARC，并考虑专家字节数不等的因素，做大小感知的淘汰。
- 投机解码联动：--spec 4 的 verify window 会触及多个专家的并集，投机深度可以按接受率和预期 miss 数动态调整，也可以用这个窗口的路由结果预取。
- 逐层配额：按层统计固定比例是否失衡，必要时做 per-layer quota。

### 方向四：decode 的 CPU miss 路径

这条路径受 DDR4 带宽限制，可以检查的点：

- 线程数是否该用 12 个物理核而不是 24 线程，SMT 对访存瓶颈的 kernel 常常是负收益；
- 线程是否按 CCD 绑定，5900X 是两个 CCD，跨 CCD 访存有代价；
- 大页：当前 vm.nr_hugepages=0，走 THP 回退；
- AVX2 的 IQ3_S 点积 kernel 本身还有多大优化空间；
- 内存频率和 FCLK 是否调到 1:1 的较优组合，硬件调优也可能带来两位数百分比。

### 方向五：模型层面的取舍（需要质量评估）

按热度给专家分级量化：热门专家用更高位宽，冷门专家用更低位宽。这样传输量和占用都能下降，但要用困惑度和任务集验证质量。相关研究可以查 Fiddler、MoE-Infinity、HOBBIT、ProMoE、Pre-gated MoE 这几个关键词；我没有逐篇核对细节，思路上与本项目的缓存、预取、混合精度很接近。

### 方向六：硬件杠杆

如果预算允许，换到 AM5（Zen 4 及以上）平台，PCIe 5.0 和 DDR5 能让传输与 CPU 路径同时提速，Zen 4 起还有 AVX-512。对这个"带宽受限"的工作负载，这可能是单项收益最大的升级，但属于花钱的选项。

### 方向七：工程与流程

- 自动化基准套件：固定 workload、固定种子、记录噪声，每次改动跑一遍，防止性能回退。
- 可观测性：把 hit rate、swap 字节数、major fault、spec 接受率等暴露为 metrics。
- 降级与总开关：前面提到的注册自检和回退梯子。
- 解耦开发环境：现在开发助手的 LLM 与被测引擎抢同一块 GPU，每次实验都要"开窗口"，是最大的流程成本。如果能让助手的 LLM 跑在别处（另一台机器、云端），或给开发配一块便宜的小 GPU 做复现，迭代速度会明显提高。

## 三、优先级建议

| 优先级 | 事项 | 理由 |
|---|---|---|
| 1 | 抓时间线 + 记录真实 prompt 分布和前缀命中率 | 成本低，决定后续排序 |
| 2 | prefill 双缓冲预取 + chunk 调优 | 针对已知的 prefill 瓶颈 |
| 3 | 前缀缓存优化（若命中率有空间） | 可能比提速 prefill 更有效 |
| 4 | usage 播种、淘汰策略、投机深度联动 | 软件改动小，风险低 |
| 5 | CPU 线程/大页/内存调优 | 要先看 decode 数据 |
| 6 | 分级量化、硬件升级 | 收益大但成本或风险高 |
