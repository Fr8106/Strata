## 3. 有出入/需保留意见的两处

1. **§2.3 的"blob 跨已注册/未注册边界"担忧不成立于现行代码**：per-blob 版注册对 run 做**向外**页对齐（`off & ~4095` 起点、`(off+bytes+4095) & ~4095` 终点），注册区间覆盖 blob 边缘页，blob 不会跨"注册/未注册"边界。0.77 GiB 缺口（35.64 − 34.87）因此不是向内取整丢页，更可能是固定区 11.2 GiB 的按专家求和与 run 覆盖的口径差 + 被跳过的短 run。跨边界这一**形态**已排除，0.77 GiB 的精确口径仍待对账（窗口内导出注册序列后一次算清）。
2. **§3.2(3) roofline 的"24 GiB/chunk ⇒ ~1 s 下限"框架不适用**：5.5–6k tok/s 目标有**实测来源**（P0 基线在本机同卡同 PCIe 上实测），不是推算；且 profile 预填（12641 slots）是**启动时一次性**行为，非每 chunk 读 24 GiB。decode 阶段的专家读取走 50/50 分层（固定区常驻显存 + 自适应区命中），不存在"每 chunk 读遍非驻留专家"的形态。roofline 作为**核对工具**有价值（窗口里顺手记 PCIe 链路状态），但不构成对目标的否定。

## 4. 采纳的行动项（进阶段 0 清单，无需 GPU 窗口）

1. **引擎侧新增**：`STRATA_PCIE_ALIAS=0` 总开关；注册序列导出（ptr/size/flags/rc/tid）；`STRATA_PCIE_ALIAS_MAX_RUNS=N` 二分旋钮；canary 自检 + 回退梯子（L1 每层 Portable → L2 pageable，降级运行而非宕机）；3 路对照拷贝（已注册 run 中部 / 未注册固定区 / 全新 pageable buffer）。
2. **server 侧**：引擎提前退出立即感知（`poll()` 快失败），不再轮询到 255 s；`strata.service` 加 `StartLimitIntervalSec`/`StartLimitBurst`。
3. **窗口脚本**：dead-man 定时器（`systemd-run --on-active` 在停 LLM 前注册）+ VRAM 预检（`nvidia-smi` memory.used 阈值循环，超时中止并恢复 LLM）+ 恢复后 8088 健康校验；窗口内带齐 `CUDA_LOG_FILE`、strace 子集、`/proc` 内存快照、PSI、PCIe 链路快照。
4. **窗口前**：`sudo dmesg -T | grep -iE 'nvrm|nvidia|uvm|xid'`；`cudaDevAttrPageableMemoryAccess` 属性查询小程序；方案 D 可行性 1–2 h 微测（HMM 已确认，条件成立）。
5. **用户裁定三件事**（窗口前）：① prefill 3.1k→5.5–6k 对日常使用的价值（典型 prompt 长度分布）；② 内存安全线（专家建议：满载 `MemAvailable` ≥ 8 GiB、swap 换入速率 0、PSI memory full avg10 < 1%）；③ 是否立项方案 B。
6. **诊断块去留**：fill 失败诊断块保留为仅失败路径运行（`STRATA_DIAG_FILL=1` 开关），其中无判别力的 unregister 探针删除或改造成"窗口 = 精确 run [base,size]"才触发。
